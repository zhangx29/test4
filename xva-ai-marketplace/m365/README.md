# Microsoft 365 Copilot agents for the XVA desk

Analysts and executives can use the same XVA MCP server from Microsoft 365 Copilot (browser, Teams, Outlook) instead of VS Code. The server, its role checks and its audit log do not change; only the front end does.

| File | Purpose |
| --- | --- |
| `xva-analyst.instructions.md` | Instructions for the analyst agent: desk rules plus the five desk workflows, condensed from the VS Code skills |
| `xva-exec-brief.instructions.md` | Instructions for the executive brief agent |

The desk rules between the markers are copied from `shared/desk-rules.md` by `scripts/sync_rules.py`. CI fails if a copy drifts or a file exceeds the 8,000-character limit for declarative agent instructions. If you commit an Agents Toolkit project under `m365/<agent>/`, CI also rejects any `capabilities` (web search, SharePoint, connectors, Teams messages, email) in `declarativeAgent.json`, so the agent answers from xva-data only.

## Option A: declarative agent with Microsoft 365 Agents Toolkit (recommended)

1. **Create the agent.** In VS Code with Microsoft 365 Agents Toolkit 6.12 or later, create a declarative agent, then add an action that starts from an MCP server: `https://xva-mcp.apps.internal.example/mcp`. Choose **Microsoft Entra SSO** and give the client ID of the XVA MCP server's Entra app.
2. **Instructions.** Paste the content of the matching `*.instructions.md` file as the agent's instructions. Add no capabilities.
3. **Entra app (Microsoft's four SSO steps).** On the XVA MCP server's app registration:
    - add the Application ID URI generated by the SSO registration to `identifierUris` (manifest editor);
    - add the Web redirect URI `https://teams.microsoft.com/api/platform/v1.0/oAuthConsentRedirect`;
    - under Expose an API, add the client application `ab3be6b7-f5df-413d-ac2d-abf1e3fd9c0b` (Microsoft Enterprise token store);
    - on the server, append that Application ID URI to `XVA_OAUTH_AUDIENCE`, and if `XVA_ALLOWED_CLIENT_IDS` is set, add `ab3be6b7-f5df-413d-ac2d-abf1e3fd9c0b`.
4. **Test.** Provision from the toolkit, open `https://m365.cloud.microsoft/chat`, pick the agent (its name ends in "dev"), sign in when prompted and run the golden questions. Save each answer as `xva-ai-platform/evals/out-m365/<id>.md` and run `python evals/score_answer.py evals/golden_questions.yaml evals/out-m365`.
5. **Deploy.** An AI Admin or Global Admin deploys the packaged agent from the Microsoft 365 admin centre (Agents) to the `xva-desk` or `xva-exec` groups only. Users cannot edit a deployed agent; changes come back through a pull request on this repo and a new package.

Reference: <https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/plugin-authentication-entra-sso>

## Option B: Copilot Studio agent

1. **Environment and credentials.** Use a dedicated Power Platform environment for XVA agents and have the Power Platform admin allow only **end-user credentials** for tools. With maker-provided credentials every user would act with the maker's access, and the server's role checks would see the maker.
2. **Connector.** Create a custom connector with OAuth 2.0 / Microsoft Entra ID and **on-behalf-of login enabled**. Resource URL = the XVA API's Application ID URI; scope `api://<api-app-id>/xva.read`. The connector's own app registration needs the delegated permission to `xva.read` and the Azure API Connections service principal (`fe053c5f-3692-4f14-aef2-ee34fc081cae`) as an authorized client application.
3. **Agent.** Turn on generative orchestration, add the MCP server through the connector, paste the instructions, and share the connector as "Can view" with users and "Can edit" with xva-ai-admins only.
4. **Server.** Tokens arrive for the API's own audience. If `XVA_ALLOWED_CLIENT_IDS` is set, add the connector app's client ID.

Reference: <https://learn.microsoft.com/en-us/microsoft-copilot-studio/advanced-custom-connector-on-behalf-of>

## Both options

- **Network:** Microsoft's cloud must reach the MCP server. Agree the route (for example Azure API Management or a private endpoint) with the network team before building; test it with one user first.
- **Licences:** declarative agents with actions need Microsoft 365 Copilot licences or metered usage enabled for the tenant.
- **Identity:** the server accepts only user-delegated tokens (they carry `scp` and the user's `oid`). An agent or connector calling as itself is refused, so desk and executive entitlements always follow the signed-in person.
- **Audit:** each audit line records the calling front end (`client`): `m365-copilot` for the token store, otherwise the client ID, or the name you map in `XVA_CLIENT_NAMES`.
